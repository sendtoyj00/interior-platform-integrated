# v0.dev 화면별 생성 프롬프트 (20개)

- **기준 문서**: 요구사항_정의서_v1.1.md (인테리어 견적·시공관리 업무 플랫폼)
- **관련 화면(SCR-*) 총계**: 20개 (7장 카테고리 커버리지 점검표 기준과 일치)
- **작성 기준**: "화면 설계서 상세 기재 항목" 가이드(기본정보/와이어프레임/디스크립션/예외처리 4대 영역) + 화면 설계서 예시 슬라이드 형식

---

## 사용 방법

1. 아래 "공통 스타일 지시사항"을 매 프롬프트 앞에 그대로 붙여서 v0.dev에 입력합니다.
2. 화면 1개 = v0.dev 요청 1회 기준입니다. (한 SCR ID에 기능이 여러 개 묶인 경우, 프롬프트 내에 상태/탭으로 구분해 하나의 화면 안에서 표현하도록 지시했습니다.)
3. 각 프롬프트의 "①②③…" 번호는 화면 설계서 디스크립션 표의 NO 컬럼과 그대로 매핑되므로, v0 결과물을 캡처한 뒤 화면 설계서 문서의 와이어프레임/디스크립션 영역에 그대로 옮겨 쓰면 됩니다.
4. `이동 화면(제안)`은 요구사항 정의서에 명시된 관련 화면 ID를 벗어나지 않는 선에서, 화면 간 흐름을 설계자가 보완한 제안값입니다. 팀 리뷰 시 확정해 주세요.

---

## 공통 스타일 지시사항 (모든 프롬프트 상단에 공통 삽입)

```text
그레이스케일(Grayscale) 와이어프레임 스타일로 만들어줘.
- 색상은 흰색/회색/검은색 계열만 사용하고, 브랜드 컬러나 화려한 그래픽은 넣지 마.
- 폰트는 시스템 기본 산세리프, 레이아웃과 정보구조·UX 흐름 표현에 집중해줘.
- 헤더(로고/역할 표시/로그아웃) / 사이드바(역할별 메뉴) / 바디(콘텐츠 영역) / 푸터(상태 메시지 영역) 구조로 영역을 구분해줘.
- 모든 상호작용 요소(버튼, 입력필드, 드롭다운, 체크박스, 모달, 토스트 등)에는 ①②③... 번호를 좌상단에 작게 표시해줘.
- 데스크톱(1920px)과 모바일(360px) 두 가지 반응형 레이아웃을 함께 보여줘 (REQ-NFR-006).
- React + Tailwind CSS로 구현하고, 실제 API 연동 없이 목업 데이터/더미 상태로 인터랙션만 구현해줘.
```

## 1. SCR-AUTH-001 — 업체 관리자 회원가입

- **대상 역할**: 업체 관리자
- **관련 요구사항**: REQ-AUTH-001 / FUNC-AUTH-001-01
- **화면 경로**: 메인 > 회원가입 > 업체

```text
업체 관리자 회원가입 화면을 만들어줘.

[초기 상태]
- 폼 진입 시 모든 입력 필드는 공란, 하단 "가입하기" 버튼은 비활성화 상태

[UI 요소]
① 상호명 입력 필드 (필수)
② 사업자등록번호 입력 필드 (필수, 000-00-00000 형식 마스크)
③ 담당자 연락처 입력 필드 (필수, 하이픈 자동 삽입)
④ 이메일 입력 필드 (필수)
⑤ 비밀번호 / 비밀번호 확인 입력 필드 (필수, 마스킹 처리, 눈모양 아이콘으로 평문/마스킹 토글)
⑥ 업체 로고 업로드 (선택, 이미지 미리보기)
⑦ 업체 소개글 텍스트영역 (선택, 최대 300자, 글자수 카운터 표시)
⑧ "가입하기" 버튼 — ①~⑤ 필수값이 유효 형식으로 모두 채워지면 활성화

[인터랙션/로직]
- ② 사업자등록번호는 형식(10자리 숫자) 검증 실패 시 필드 하단에 빨간 에러 문구 표시
- ⑧ 클릭 시 로딩 스피너 표시 → "이메일 인증 메일을 발송했습니다" 안내 화면으로 전환
- 이메일 인증 완료 시 "플랫폼 관리자 승인 대기 중" 상태 안내 화면 표시 (승인 전까지 로그인 불가 안내 포함)

[예외 처리]
- 이미 가입된 이메일/사업자등록번호 입력 시 각 필드 하단에 "이미 등록된 정보입니다" 에러 표시
- 네트워크 오류 시 하단 토스트 메시지 노출

[이동 화면(제안)]
- 인증 완료 후 승인 대기 안내 화면 → 로그인 화면(SCR-AUTH-003)으로 이동 가능
```

- **대상 역할**: 인테리어 고객
- **관련 요구사항**: REQ-AUTH-001 / FUNC-AUTH-001-02

```text
인테리어 고객 회원가입 화면을 만들어줘. (업체 관리자 가입보다 간단한 간편가입 형태)

[UI 요소]
① 이름 입력 필드 (필수)
② 이메일 또는 휴대폰번호 입력 필드 (필수, 탭으로 이메일/휴대폰 선택)
③ 비밀번호 / 비밀번호 확인 입력 필드 (필수, 마스킹)
④ 주소 입력 필드 (선택, "나중에 입력하기" 링크 병기)
⑤ 약관 동의 체크박스 (필수, 전체동의 + 개별 항목 아코디언)
⑥ "가입하기" 버튼 — ①②③⑤ 완료 시 활성화

[인터랙션/로직]

- ⑥ 클릭 후 이메일 인증 완료 시 별도 승인 절차 없이 즉시 계정 활성화 → 로그인 화면으로 자동 이동

[예외 처리]
- 인증번호 오입력 3회 시 "재발송" 유도 문구로 전환
- 이미 가입된 이메일/휴대폰 시 필드 하단 에러 표시

[이동 화면(제안)]
- 가입 완료 즉시 → 로그인 화면(SCR-AUTH-003)
```

## 3. SCR-AUTH-003 — 로그인 / 로그아웃

- **대상 역할**: 전체 사용자 (업체관리자/현장담당자/고객/플랫폼관리자)
- **관련 요구사항**: REQ-AUTH-002 / FUNC-AUTH-002-01, FUNC-AUTH-002-02
- **화면 경로**: 메인 > 로그인

```text
전체 사용자 공용 로그인 화면을 만들어줘.

[UI 요소]
① 이메일 입력 필드
② 비밀번호 입력 필드 (마스킹, 눈모양 토글)
③ "로그인 상태 유지" 체크박스
④ "로그인" 버튼 — ①② 유효 형식 입력 시 활성화
⑤ 하단 텍스트 링크: "비밀번호를 잊으셨나요?" / "회원가입"
⑥ (헤더 우측, 로그인 후에만 노출) 사용자명 + "로그아웃" 버튼

[인터랙션/로직]
- ④ 클릭 시 로딩 스피너 → 인증 성공 시 JWT 발급, 역할에 따라 자동 분기 이동
  - 업체관리자 → 업체 대시보드 / 현장담당자 → 공정관리 화면 / 고객 → 고객 마이페이지 / 플랫폼관리자 → 업체 승인관리 화면
- ⑥ "로그아웃" 클릭 시 확인 모달("로그아웃 하시겠습니까?") → 확인 시 토큰 폐기 후 로그인 화면으로 이동

[예외 처리]
- 이메일/비밀번호 불일치 시 ②필드 하단에 "이메일 또는 비밀번호가 올바르지 않습니다" 에러 표시
- 승인 대기 중인 업체 계정으로 로그인 시도 시 "플랫폼 관리자 승인 후 이용 가능합니다" 안내 모달
- 5회 이상 로그인 실패 시 캡차(CAPTCHA) 인증 모달 노출

[이동 화면(제안)]
- SCR-DASH-001(업체) / SCR-PROC-001(현장담당자) / SCR-DASH-002(고객) / SCR-COMP-001(플랫폼관리자)
- ⑤ 링크 → SCR-AUTH-004(비밀번호 재설정), SCR-AUTH-001/002(회원가입)
```

## 4. SCR-AUTH-004 — 비밀번호 재설정 / 변경

- **대상 역할**: 전체 사용자
- **관련 요구사항**: REQ-AUTH-003 / FUNC-AUTH-003-01, FUNC-AUTH-003-02
- **화면 경로**: 메인 > 로그인 > 비밀번호 찾기 (비로그인) / 마이페이지 > 비밀번호 변경 (로그인)

```text
비밀번호 재설정 화면을, 비로그인 상태의 "비밀번호 찾기"와 로그인 상태의 "비밀번호 변경" 두 가지 상태(state)로 전환 가능하게 만들어줘. 상단 탭 또는 진입 경로에 따라 자동으로 상태가 결정되는 것으로 표현해줘.

[상태 A: 비밀번호 찾기 (비로그인)]
① 가입 이메일 입력 필드
② "재설정 링크 받기" 버튼
- 클릭 시 "재설정 링크를 이메일로 발송했습니다. 30분 이내에 확인해주세요" 안내 화면으로 전환
- 30분 경과 후 링크 클릭 시 "만료된 링크입니다. 다시 요청해주세요" 에러 화면

[상태 B: 비밀번호 변경 (로그인 상태)]
③ 현재 비밀번호 입력 필드
④ 신규 비밀번호 입력 필드 (최소 길이/조합 규칙 실시간 안내 문구, REQ-NFR-001)
⑤ 신규 비밀번호 확인 입력 필드
⑥ "변경하기" 버튼 — ③④⑤ 유효 시 활성화

[예외 처리]
- ③ 현재 비밀번호 불일치 시 필드 하단 에러 표시
- ④⑤ 불일치 시 "비밀번호가 일치하지 않습니다" 에러 표시
- 미가입 이메일로 재설정 요청 시에도 보안상 동일한 "발송했습니다" 문구 노출(계정 존재 여부 노출 방지)

[이동 화면(제안)]
- 재설정/변경 완료 시 SCR-AUTH-003(로그인 화면)으로 이동
```

## 5. SCR-AUTH-005 — 역할기반 접근권한(RBAC) 관리

- **대상 역할**: 플랫폼 관리자
- **관련 요구사항**: REQ-AUTH-004 / FUNC-AUTH-004-01
- **화면 경로**: 메인 > 시스템관리 > 권한관리

```text
플랫폼 관리자용 역할별 접근권한 관리 화면을 만들어줘.

[UI 요소]
① 역할 선택 탭: 업체관리자 / 현장담당자 / 고객 / 플랫폼관리자
② 선택된 역할이 접근 가능한 메뉴 목록 테이블 (메뉴명 / 화면ID / 접근허용 토글 스위치)
③ 선택된 역할의 API 접근범위 표시 테이블 (API 경로 / Method / 허용여부 뱃지, 읽기 전용)
④ "변경사항 저장" 버튼 (② 토글 변경 시에만 활성화)
⑤ 저장 이력 리스트 (변경자/변경일시/변경내용 — 감사로그, REQ-NFR-004)

[인터랙션/로직]
- ② 토글 변경 시 우측 상단에 "저장되지 않은 변경사항" 배지 표시
- ④ 클릭 시 확인 모달("이 변경사항은 즉시 전체 사용자에게 적용됩니다") → 확인 시 저장 및 토스트 안내

[예외 처리]
- 플랫폼관리자 역할 자체의 접근권한은 토글 비활성화(수정 불가) 처리
- 저장 실패 시 "권한 변경에 실패했습니다. 다시 시도해주세요" 토스트

[비고]
- 이 화면은 프론트 UI일 뿐이며, 실제 강제는 백엔드 JWT 클레임 검증에서 이루어짐(REQ-NFR-002) — 화면 하단에 안내 문구로 명시
```

## 6. SCR-COMP-001 — 업체 등록 및 승인 관리

- **대상 역할**: 플랫폼 관리자
- **관련 요구사항**: REQ-COMP-001 / FUNC-COMP-001-01, FUNC-COMP-001-02
- **화면 경로**: 메인 > 업체관리 > 승인관리

```text
플랫폼 관리자용 업체 가입 승인 관리 화면을 만들어줘.

[UI 요소]
① 상태 필터 탭: 승인대기 / 승인완료 / 반려
② 업체 목록 테이블 (상호명 / 사업자등록번호 / 담당자연락처 / 가입신청일 / 상태뱃지)
③ 테이블 행 클릭 시 우측 상세 패널 슬라이드 오픈 (사업자정보 전체 + 업로드된 로고/소개글 미리보기)
④ 상세 패널 내 "승인" 버튼
⑤ 상세 패널 내 "반려" 버튼
⑥ 반려 사유 입력 모달 (⑤ 클릭 시 노출, 필수 입력)

[인터랙션/로직]
- ④ 클릭 시 확인 모달 → 확인 시 해당 업체 상태를 "승인완료"로 전환, 계정 활성화, 목록에서 상태뱃지 갱신
- ⑤→⑥ 사유 입력 후 "반려 확정" 시 상태를 "반려"로 전환하고 사유를 이력으로 영구 보관(수정 불가)

[예외 처리]
- 반려 사유 미입력 시 "반려 확정" 버튼 비활성화
- 이미 처리된(승인/반려) 건에 대해서는 ④⑤ 버튼 비노출, "처리완료" 텍스트만 표시

[이동 화면(제안)]
- 승인 시 해당 업체 관리자에게 알림 발송(SCR-NOTI-001 트리거) — 화면 자체는 그대로 목록 유지
```
